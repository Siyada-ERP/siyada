## [Unreleased]

### Fixed
- تحسين التحديث التلقائي لنسخة Windows بإظهار سبب فشل التحقق أو التنزيل وتسجيل تقدم التحديث.

### Fixed
- Browser tests `t7_new` / `t9_weight` could fail on slow machines (first seen on GitHub Actions: `1202 balance after edit 900`): they waited for `#frm[data-edit]`, which also matches the create form still on screen, so the amount was typed into the old form. They now wait for the edit form and the create form explicitly, and `t7_new` route changes wait until the screen has really been replaced.
- Starting the server from a source checkout failed with `ENOENT … server/public/index.html` because that file is generated by the build and is not stored in git. The server now falls back to `dist/SIYADA.html`, prints an Arabic explanation with the fix when neither exists, and `start-windows.bat` / `start.sh` build the page automatically on first run.

### Changed
- إضافة نظام مخازن متعدد: مخزن رئيسي افتراضي، مخازن إضافية، اختيار المخزن اختياريًا في الفواتير، تحويل مباشر بين المخازن، وأرصدة وتكلفة مستقلة لكل مخزن مع ترحيل البيانات القديمة تلقائيًا للمخزن الرئيسي.
- إعادة تنظيم **إعدادات المشروع** في أقسام واضحة: الشركة والهوية، المحاسبة والضريبة، المخزون، الفواتير، والمستخدمون. إعدادات الشكل تُطبّق الآن مباشرة على الواجهة، مع دعم المظهر الأزرق الحديث.
- فصل شاشة **الأصناف** عن شاشة **المخازن**: الأصناف تعرض البيانات الأساسية والتعريفات، بينما تعرض المخازن الأرصدة والتكلفة والقيمة والتنبيهات، مع إبقاء حركة المخزون كتقرير مستقل.
- تحسين مظهر عناوين الشاشات والجداول، وإعادة تسمية دليل الحسابات إلى **شجرة الحسابات** مع تمييز مجموعات الحسابات بصريًا.
- إضافة تصدير موحد لتقارير الجداول بصيغة Excel المتوافقة مع Microsoft Excel، مع زر PDF عبر حوار الطباعة، مع الحفاظ على تصدير CSV.
- إضافة أزرار طباعة المستندات بمقاسي A4 وA5، مع إظهار حساب الدفع وبيانات البنك أو المحفظة في الفاتورة.
- توسيع إعدادات البرنامج لتشمل مقاس الطباعة الافتراضي، العملة، وسائل الدفع المفعّلة، وإضافة شاشة معلومات الإصدار وحالة البيانات.
- إضافة حماية محلية اختيارية بكلمة مرور، مع شاشة قفل عند بدء التشغيل وإمكانية تغيير كلمة المرور أو تعطيلها من إعدادات البرنامج.
- `tests/e2e/run_all.py --retry=N` re-runs a failing suite (CI uses `--retry=1`); a suite that only passes on retry is reported as FLAKY with a GitHub warning, and the end of the output lists every failing check.
- Dependabot groups GitHub-Actions and Python updates into one pull request each and keeps at most 2 open per ecosystem.

## [1.0.0] - 2026-11-02

First version organised as a repository. It contains everything built so far.

### Application
- Double-entry posting engine with consistency checks; no formulas anywhere.
- Sales and purchase invoices, returns, receipt / payment vouchers, expenses, income, transfers, manual journal entries.
- Items with moving-average cost, reorder level, price lists; per-item **weight** (kg / litre per unit) with automatic **pieces = quantity ÷ weight** on invoice lines.
- **Sales / purchase registers** (one row per invoice with line count, expandable lines, view / edit / delete) and **net quantity after returns** per customer, supplier or item over a period.
- Reports: general ledger, trial balance, income statement, balance sheet, party statements, treasury, VAT report, e-invoice (ETA) draft, year-end closing.
- **Employees**: master data, advances and repayments, monthly payroll with advance deduction, payslip, employee statement and monthly advances sheet.
- Dexef-style **top menu bar** (headings with drop-downs and fly-outs, mobile drawer) replacing the sidebar.
- Company name entered once and applied to every screen, report and print header.
- Import of the CSV export of the Excel ERP, tied out to the cent.

### Server
- Multi-company, multi-user Node.js server (no npm dependencies, SQLite via `node:sqlite`).
- Roles: owner, accountant, viewer — enforced server-side.
- Invitations, e-mail verification and password reset (SMTP optional), activity log, admin console, CLI.
- Diff-based sync with conflict detection, long-poll updates and server-allocated document numbers; employees included in sync.
- Daily automatic backups, Docker + Caddy (automatic HTTPS) and systemd deployment files.

### Repository
- Layout `client/ server/ scripts/ tests/ docs/ .github/`; one `npm run build` produces `dist/SIYADA.html`.
- Tests: engine tie-out (2 fixture sets), 108 server assertions, 9 browser suites run by `tests/e2e/run_all.py`.
- GitHub Actions: CI (build, engine, server, browser, Docker) and tag-driven release.
- Anonymised fixtures and `scripts/anonymize_fixtures.py`.
